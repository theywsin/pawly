# راهنمای نصب مهندیکس روی سرور

## ۱. پیش‌نیازها

- سرور لینوکس ۶۴ بیتی (x86_64)، مثلاً Ubuntu 22.04 یا 24.04
- حداقل ۴ گیگابایت RAM، ۲ هسته و ۴۰ گیگابایت دیسک
- Docker Engine نسخه ۲۴ یا بالاتر، همراه افزونه `docker compose`
- ابزار `openssl` (در بیشتر توزیع‌ها از قبل نصب است)
- برای HTTPS خودکار:
  - یک دامنه که رکورد A آن به IP سرور اشاره کند
  - پورت‌های ۸۰ و ۴۴۳ باز باشند

تمام ایمیج‌ها داخل همین بسته در `images/` هستند و نصب به اینترنت یا Docker Hub نیازی ندارد. فقط گرفتن گواهی HTTPS خودکار از Let's Encrypt به اینترنت نیاز دارد.

## ۲. نصب

```bash
tar xzf mohandix.tar.gz
cd mohandix
sudo ./install.sh
```

اسکریپت این سؤال‌ها را می‌پرسد:

1. **دامنه**:
   - مثلاً `example.ir`، تا گواهی HTTPS خودکار گرفته شود.
   - یا فقط یک شماره پورت (مثلاً `5000`) برای HTTP ساده روی IP سرور، وقتی پورت ۸۰ در اختیار برنامه دیگری است (فقط برای آزمایش).
   - اگر پورت انتخابی اشغال باشد، اسکریپت پیش از شروع خبر می‌دهد.
2. **ایمیل و رمز مدیر سامانه**: برای ورود به پنل مدیریت در `/console`. رمز باید حداقل ۱۲ نویسه باشد.

سپس اسکریپت این کارها را انجام می‌دهد:

- ایمیج‌ها را بارگذاری می‌کند.
- فایل `.env` را با رمزهای تصادفی تازه می‌سازد.
- پایگاه داده را مهاجرت می‌دهد.
- همه ۱۲ ماژول امضاشده پوشه `modules/` را نصب می‌کند.

در پایان نشانی سامانه را نمایش می‌دهد.

**نصب خودکار (بدون پرسش):**

```bash
SITE_ADDRESS=example.ir ADMIN_EMAIL=admin@example.ir ADMIN_PASSWORD='...' sudo -E ./install.sh
```

**ورود اول به پنل مدیریت:** پس از ورود به `/console`، تأیید دومرحله‌ای (برنامه Authenticator) را فعال کنید. پنل بدون آن باز نمی‌شود.

## ۳. تنظیمات (`.env`)

پس از هر تغییر در `.env` دستور `docker compose up -d` را اجرا کنید.

| متغیر | کاربرد |
|---|---|
| `SITE_ADDRESS` | دامنه سایت، یا `:80` برای HTTP ساده (پورت بیرونی در `HTTP_PORT`) |
| `PUBLIC_ORIGIN` | نشانی دقیقی که کاربران باز می‌کنند. پیوندهای دانلود فایل هم با همین نشانی امضا می‌شوند. |
| `HTTP_PORT` / `HTTPS_PORT` | پورت‌های سرور. پیش‌فرض ۸۰ و ۴۴۳ است. |
| `SMTP_URL`، `MAIL_FROM` | ارسال ایمیل اعلان‌ها. اگر خالی بماند، اعلان‌ها فقط درون برنامه نمایش داده می‌شوند. |
| `API_WORKERS` | تعداد پردازه‌های سرور |

مقادیر `.env` (به‌ویژه `APP_ENCRYPTION_KEY`) و فایل `s3.json` را جای امنی نگه دارید.

## ۴. پشتیبان‌گیری و بازیابی

**پشتیبان‌گیری:**

```bash
sudo ./backup.sh                          # پوشه backups/<زمان>/
sudo ./restore.sh backups/20261016-094651
```

`backup.sh` این موارد را ذخیره می‌کند:

- پایگاه داده
- فایل‌های بارگذاری‌شده
- بسته‌های ماژول
- `.env` و `s3.json`
- کلید عمومی

برای پشتیبان‌گیری روزانه، یک cron بسازید، مثلاً:

```
0 3 * * * /opt/mohandix/backup.sh
```

پوشه `backups/` را بیرون از سرور هم نگه دارید.

**بازیابی:** `restore.sh` داده فعلی را کاملاً جایگزین می‌کند. پس از آن، یکی دو دقیقه طول می‌کشد تا ذخیره‌ساز فایل کاملاً بالا بیاید.

## ۵. ارتقا

1. بسته جدید را در همان پوشه باز کنید. فایل‌های `.env`، `s3.json` و `backups/` دست نمی‌خورند.
2. دستور `sudo ./install.sh` را دوباره اجرا کنید. ایمیج‌های تازه بارگذاری و مهاجرت‌ها اجرا می‌شوند.

پیش از ارتقا حتماً با `backup.sh` پشتیبان بگیرید.

## ۶. درگاه پرداخت سپ (بانک سامان)

1. از بانک سامان «درگاه پرداخت اینترنتی» (ترمینال) بگیرید.
2. در پنل پذیرندگی بانک، **نشانی بازگشت** را این آدرس ثبت کنید (همان را در پنل مدیریت ← «پرداخت و فروش» ← «درگاه و تنظیمات» هم می‌بینید):
   `https://دامنه-شما/api/public/payments/sep/callback`
3. در همان صفحه، شماره ترمینال را وارد و «پرداخت آنلاین فعال باشد» را بزنید. درصد مالیات و طول دوره آزمایشی هم همان‌جا تنظیم می‌شوند.
4. در «قیمت ماژول‌ها» برای ماژول‌هایی که جداگانه فروخته می‌شوند قیمت بگذارید و در «پلن‌ها» قیمت پلن‌ها را.
5. **اولین پرداخت واقعی را با یک پلن کم‌مبلغ خودتان انجام دهید** و بعد در «پرداخت‌ها» وضعیت «موفق» و شماره پیگیری را ببینید.

متغیر `PAYMENT_SANDBOX` (درگاه آزمایشی بدون پول) را روی سرور اصلی هرگز فعال نکنید.

## ۷. انتشار ماژول جدید

ماژول‌ها با کلید خصوصی امضا می‌شوند. سرور فقط بسته‌هایی را می‌پذیرد که امضای آن‌ها با `keys/release.pub.pem` بخواند.

- کلید خصوصی (`release.key.pem`) **جدا از بسته** به شما تحویل داده شده است.
- آن را روی سرور نگذارید و از آن نسخه پشتیبان امن نگه دارید.
- اگر این کلید گم شود، نسخه جدیدی از ماژول‌ها نمی‌توان منتشر کرد.

مراحل انتشار، در مخزن کد:

```bash
pnpm module:pack modules/<نام> --out out
pnpm module:sign out/<نام>-<نسخه>.mypkg --key release.key.pem
```

سپس فایل `.mypkg` را در پنل مدیریت، بخش «ماژول‌ها» بارگذاری و نصب کنید.

## ۸. عیب‌یابی

```bash
docker compose ps                  # وضعیت سرویس‌ها
docker compose logs -f api         # گزارش سرور
docker compose logs migrate        # خطای مهاجرت
docker compose restart api
```

- **گواهی HTTPS صادر نشد:** بررسی کنید رکورد DNS درست تنظیم شده و پورت‌های ۸۰ و ۴۴۳ باز باشند. سپس `docker compose logs proxy` را ببینید.
- **دانلود فایل‌ها کار نمی‌کند:** مقدار `PUBLIC_ORIGIN` باید دقیقاً همان نشانی‌ای باشد که در مرورگر باز می‌شود.
