# ماژول پروژه‌ها (`projects`)

مدیریت پروژه‌های مهندسی و عمرانی: تعریف پروژه، تیم، برنامه زمان‌بندی با مسیر بحرانی، پیشرفت برنامه‌ای و واقعی، موانع، ریسک‌ها، گزارش روزانه کارگاه، درخواست تغییر و تحویل مراحل.

## قابلیت‌ها

| بخش | توضیح |
|---|---|
| پروژه | کد (یکتا در شرکت)، عنوان، نوع، کارفرما (متن آزاد یا طرف حساب CRM)، مدیر پروژه، محل اجرا، مشخصات فنی، تاریخ شروع/پایان برنامه‌ای و واقعی، بودجه، وضعیت (برنامه‌ریزی، در حال اجرا، متوقف، تکمیل، لغو)؛ قفل خوش‌بینانه |
| تیم | اعضا با نقش در پروژه (مدیر، مهندس، ناظر، کارگاه، عضو)؛ مدیر پروژه خودکار عضو است |
| ساختار شکست کار (WBS) | فعالیت‌های درختی؛ فعالیت خلاصه (دارای زیرفعالیت) بازه زیرفعالیت‌ها را می‌گیرد؛ مدت ۰ = نقطه عطف؛ وزن نسبی برای محاسبه پیشرفت |
| تقویم کاری | مدت فعالیت‌ها به **روز کاری** است: جمعه‌ها (قابل تغییر)، تعطیلات رسمی ثابت شمسی (محاسبه خودکار) و تعطیلات قمری/سازمانی ثبت‌شده در «تنظیمات ← تقویم کاری» کار حساب نمی‌شوند؛ با تغییر تقویم، برنامه دوباره محاسبه می‌شود (نسخه 1.1.0) |
| وابستگی و مسیر بحرانی | FS/SS/FF/SF با تأخیر یا تقدم (روز)؛ فقط بین فعالیت‌های جزء؛ حلقه رد می‌شود (و نام فعالیت‌های حلقه گفته می‌شود). پس از هر تغییر، CPM (رفت و برگشت) اجرا و ES/EF/LS/LF، شناوری کل، بحرانی بودن و تاریخ‌های برنامه‌ای ذخیره می‌شود |
| گانت | نمودار SVG راست‌به‌چپ با ماه‌های شمسی، میله برنامه‌ای، پیشرفت واقعی، فعالیت‌های بحرانی به رنگ هشدار، خط امروز |
| پیشرفت | هر ثبت = درصد تجمعی فیزیکی یک فعالیت در یک تاریخ (تاریخچه حفظ می‌شود). **فیزیکی:** واقعی = میانگین وزنی درصد فعالیت‌ها؛ برنامه‌ای = پیشرفت خطی هر فعالیت در بازه برنامه‌ای. **زمانی:** روزهای سپری‌شده نسبت به مدت برنامه‌ای. **مالی:** کارکرد تأییدشده قراردادهای درآمدی متصل نسبت به مبلغ جاری آن‌ها (اگر ماژول قراردادها فعال باشد). منحنی S برنامه‌ای/واقعی از همین داده‌ها ساخته می‌شود |
| تأخیر، مانع، مسئله | نوع، علت، اثر بر زمان، مسئول (اعلان دریافت می‌کند)، مهلت، رفع |
| ریسک | احتمال × اثر (۱ تا ۵)، پاسخ، مالک، باز/بسته |
| گزارش روزانه | یک گزارش برای هر روز: هوا، نیرو، تجهیزات، کارهای انجام‌شده، مشکلات |
| درخواست تغییر | اثر هزینه و زمان؛ ارسال به گردش تأیید `projects.change_request` (پیش‌فرض: مدیر شرکت)؛ نتیجه با رویداد `core.workflow.completed` |
| مراحل و تحویل | مرحله، تحویل موقت، تحویل قطعی؛ ثبت تاریخ تحویل و تأیید کارفرما |
| داشبورد | «پروژه‌های فعال و دارای تأخیر» (پیشرفت واقعی/برنامه‌ای) و «موانع و ریسک‌های باز» |

«دارای تأخیر»: پروژه در حال اجرایی که پیشرفت برنامه‌ای آن بیش از آستانه تنظیمات (پیش‌فرض ۵ درصد) از پیشرفت واقعی جلوتر است.

## مجوزها و محدوده پروژه

| کلید | محدوده‌ها |
|---|---|
| `projects.project.view` | company (همه پروژه‌ها) / project (فقط پروژه‌هایی که عضو تیم یا مدیر آن هستید) |
| `projects.project.create` | company |
| `projects.project.update` | company / project — مشخصات، تیم، مراحل |
| `projects.project.delete` | company — فقط پروژه بدون پیشرفت ثبت‌شده |
| `projects.schedule.edit` | company / project — فعالیت‌ها و وابستگی‌ها |
| `projects.progress.record` | company / project — پیشرفت، گزارش روزانه، تأخیر/مانع، ریسک |
| `projects.change.create` | company / project |

نقش‌های پیش‌فرض: «مدیر پروژه‌ها» (`projects.*` در کل شرکت) و «عضو تیم پروژه» (مشاهده، ثبت پیشرفت و درخواست تغییر **فقط در پروژه‌های عضو**). مجوز نقش در manifest با قالب `کلید@محدوده` تعریف می‌شود.

## وابستگی‌ها
- **اختیاری:** `contracts` (پیشرفت مالی، فهرست قراردادهای متصل)، `crm` (انتخاب کارفرما).
- **سرویس عمومی:** `projects.projects@1.0.0` — `search(q, limit)`، `get(id)`.
- **رویدادها:** منتشر می‌کند `projects.project.created`، `projects.change_request.approved`؛ مصرف می‌کند `core.workflow.completed`.

## محدودیت‌های نسخه ۱
- نسخه پایه (baseline) برنامه و مقایسه با آن، نمایش پیکان وابستگی‌ها در گانت و جابه‌جایی فعالیت در درخت هنوز ساخته نشده‌اند.
- تصاویر، نقشه‌ها و نسخه‌بندی اسناد پروژه به ماژول اسناد (فاز ۵) سپرده شده است.
- خروجی Excel/PDF گزارش‌ها هنوز ساخته نشده است.
