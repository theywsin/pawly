# ماژول شاخص‌های عملکرد (`kpi`)

| بخش | توضیح |
|---|---|
| تعریف شاخص | نام، کد (برای فرمول)، توضیح، واحد، جهت مطلوب (بیشتر/کمتر بهتر)، سطح (سازمان، واحد، پروژه، نقش، فرد)، دوره (ماهانه/فصلی/سالانه شمسی)، منبع (ورود دستی، Provider ماژول فعال، فرمول)، وزن، آستانه مطلوب و هشدار (درصد تحقق هدف؛ کمتر از هشدار = بحرانی)، «شرط لازم» برای ایمنی/کیفیت/انطباق، مسئول؛ **نسخه‌دار** (هر ذخیره نسخه جدید و مقدار نسخه‌ای را که با آن ثبت شده نگه می‌دارد). |
| فرمول | زبان محاسباتی محدود با پارسر دست‌نویس (بدون eval): اعداد، کد شاخص‌های هم‌سطح و هم‌دوره، `+ - * /`، پرانتز، `min` `max` `abs` `round`؛ کنترل کد ناشناخته، ارجاع به خود و حلقه؛ فقط از مقادیر **تأییدشده** همان دوره و موضوع؛ تقسیم بر صفر = بدون نتیجه. |
| Provider | شاخص‌هایی که ماژول‌های فعال در manifest اعلام کرده‌اند (مثلاً `hr.headcount`، `recruitment.hires`، `contracts.signed_value`) از طریق ثبت‌نام Provider در هسته، در محدوده سازمان و شرکت کاربر اجرا می‌شوند؛ مقدار با «عکس» منبع (Provider، ماژول، بازه تاریخ، زمان محاسبه) ذخیره می‌شود. |
| هدف و مقدار | هدف برای هر دوره و موضوع؛ مقدار دستی (مسئول شاخص یا مدیر شاخص‌ها) یا محاسبه‌شده، همه با وضعیت «در انتظار تأیید»؛ **ثبت‌کننده نمی‌تواند تأیید کند**؛ رد با دلیل؛ مقدار تأییدشده فقط پس از «بازگشایی» قابل اصلاح است؛ تاریخچه کامل هر مقدار. |
| روند تاریخی | نمودار مقدار تأییدشده در برابر هدف برای هر موضوع (SVG، بدون کتابخانه خارجی). |
| کارت امتیاز | امتیاز هر شاخص = تحقق هدف (حداکثر ۱۲۰٪)، میانگین وزنی؛ فقط مقادیر تأییدشده؛ کارت ناقص قابل تأیید نیست؛ شرط لازم نامطلوب یا بدون داده = «شرط لازم برقرار نیست»؛ پیش‌نویس ← بازبینی ← تأیید نهایی (تأییدکننده ≠ بازبین ≠ خود فرد)؛ محاسبه دوباره کارت تأییدشده نسخه جدید می‌سازد و نسخه قبلی «نسخه قبلی» می‌شود. |
| ضریب پاداش | قاعده نسخه‌دار (بازه‌های امتیاز → ضریب، ضریب حالت شرط لازم)؛ پس از تأیید نهایی کارت، ضریب با نسخه فعال قاعده **فقط به‌عنوان پیشنهاد** ثبت می‌شود؛ این ماژول هیچ مبلغ، پرداخت یا اتصالی به حقوق ندارد. |
| داشبورد | ویجت «وضعیت شاخص‌ها» (مطلوب/هشدار/بحرانی، موارد نیازمند توجه، مقادیر در انتظار تأیید). |

## مجوزها
`kpi.view` (own: شاخص‌هایی که مسئول آن هستید و کارت امتیاز خودتان)، `kpi.definition.manage`، `kpi.value.enter` (own: شاخص‌های مسئولیت خود)، `kpi.value.approve`، `kpi.scorecard.review`، `kpi.scorecard.approve`، `kpi.reward.manage`. نقش‌ها: «مدیر شاخص‌های عملکرد» (بدون تأیید)، «تأییدکننده شاخص‌ها»، «مسئول شاخص».

## محدودیت‌ها
- Providerهای فعلی در سطح شرکت محاسبه می‌شوند و بُعد موضوع (فرد/واحد/پروژه) را نادیده می‌گیرند (A46).
- زمان‌بندی خودکار دریافت مقادیر از Providerها ندارد؛ دریافت با دکمه انجام می‌شود.
