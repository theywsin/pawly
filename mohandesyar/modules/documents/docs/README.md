# ماژول مدیریت اسناد (`documents`)

| بخش | توضیح |
|---|---|
| پوشه و دسته | درخت پوشه (جلوگیری از حلقه، حذف فقط پوشه خالی)؛ دسته تعیین می‌کند نسخه‌ها تأیید لازم دارند یا نه و کدام سیاست نگهداری اعمال شود. |
| سند | شماره یکتا در شرکت، عنوان، شرح، برچسب‌ها، مالک، سطح محرمانگی، تاریخ انقضا و روزهای یادآوری. |
| جست‌وجو | متن کامل PostgreSQL (`simple`) + `pg_trgm` روی شماره، عنوان، شرح، برچسب و نام فایل‌ها با نرمال‌سازی فارسی (ی/ي، ک/ك، ارقام)؛ فیلتر پوشه، دسته، برچسب، وضعیت، انقضا و اتصال. نتایج در جست‌وجوی سراسری هم با همان قاعده دسترسی. |
| نسخه‌بندی | هر نسخه یک فایل؛ نسخه جدید به گردش `documents.version` می‌رود (پیش‌فرض: کنترل‌کننده اسناد؛ بارگذار نمی‌تواند تأیید کند — قاعده هسته). نسخه تأییدشده نسخه جاری می‌شود و **تغییرناپذیر** است (trigger پایگاه داده)؛ نسخه قبلی «جایگزین‌شده». در هر زمان یک نسخه در انتظار؛ پس‌گرفتن نسخه در انتظار فایلش را پاک می‌کند. خوانندگان فقط نسخه‌های تأییدشده را می‌بینند. |
| محرمانگی | **عادی**: هر کس `documents.view` در محدوده‌اش (company همه؛ project اسناد متصل به پروژه‌های خود یا ساخته خودش؛ own ساخته خودش). **محرمانه**: مالک، فهرست دسترسی و مدیر اسناد. **سری**: فقط مالک و فهرست دسترسی. فهرست دسترسی را مالک (و برای غیرسری مدیر اسناد) تعیین می‌کند. تغییر سطح محرمانگی فقط با مالک یا مدیر. |
| ثبت مشاهده و دانلود | برای اسناد محرمانه و سری، هر بازکردن جزئیات و هر دانلود در جدول append-only ماژول و Audit هسته ثبت می‌شود؛ مالک (و مدیر برای محرمانه) سابقه را می‌بیند. |
| اتصال | به پروژه، قرارداد، درخواست پرداخت (ماژول مالی) و کاربر؛ وجود مورد هنگام اتصال بررسی می‌شود (فقط ماژول‌های فعال). در محدوده project، سند جدید باید به یکی از پروژه‌های کاربر متصل باشد و همین اتصال قابل قطع نیست. |
| انقضا | یادآوری به مالک از «انقضا − روزهای یادآوری»، یک‌بار برای هر تاریخ انقضا (کار زمان‌بندی‌شده)؛ ویجت «اسناد رو به انقضا». |
| نگهداری و امحا | دوره نگهداری = تاریخ تأیید نخستین نسخه + سال‌های سیاست دسته؛ تغییر سیاست یا دسته، تاریخ را دوباره محاسبه می‌کند. سند دارای نسخه تأییدشده هرگز حذف نمی‌شود (فقط منسوخ)؛ پس از پایان دوره، اعلان به مالک و فهرست «پایان دوره نگهداری» برای مدیر؛ امحا دستی با دلیل: فایل همه نسخه‌ها پاک و رکورد، سابقه نسخه‌ها و دسترسی‌ها به‌عنوان مدرک باقی می‌ماند. |
| داشبورد و KPI | ویجت اسناد رو به انقضا و نسخه‌های در انتظار تأیید؛ Providerهای KPI: اسناد منقضی، نسخه‌های در انتظار تأیید. |

## مجوزها
`documents.view` (company/project/own)، `documents.manage` (company/project)، `documents.admin`. نقش‌ها: «کنترل‌کننده اسناد» (همه + تأییدکننده پیش‌فرض)، «ثبت‌کننده اسناد پروژه» (پروژه‌های خود)، «خواننده اسناد». دو نقش اول مجوز هسته `core.file.upload@own` را هم دارند تا بتوانند فایل بارگذاری کنند.

## محدودیت‌ها
- فهرست دسترسی فقط کاربر به کاربر است (نه نقش) — A51.
- پیش‌نمایش درون مرورگر و جست‌وجو در متن داخل فایل (OCR/PDF) ندارد؛ جست‌وجو روی مشخصات و نام فایل است.
- قفل/Check-out هم‌زمان ندارد؛ هر بار یک نسخه در انتظار مجاز است.
