# ماژول قراردادها (`contracts`)

ثبت و پیگیری قراردادهای درآمدی و هزینه‌ای شرکت: کارفرمایی، پیمانکاری، مشاوره، خرید و خدمات.

## قابلیت‌ها

| بخش | توضیح |
|---|---|
| قرارداد | شماره (یکتا در شرکت)، عنوان، نوع، جهت مالی (درآمدی/هزینه‌ای)، طرف قرارداد، مسئول، مبلغ اولیه، پیش‌پرداخت، تاریخ شروع/پایان، نرخ کسورات، اتصال اختیاری به پروژه و طرف حساب CRM |
| چرخه عمر | پیش‌نویس ← (ثبت امضا) جاری ← پایان‌یافته یا فسخ‌شده. پیش‌نویس آزادانه ویرایش و حذف می‌شود؛ پس از امضا **مبلغ، مدت و نرخ کسورات فقط با الحاقیه** تغییر می‌کند. ویرایش هم‌زمان با قفل خوش‌بینانه (`version`) رد می‌شود |
| الحاقیه و تمدید | تغییر مبلغ (مثبت/منفی)، تغییر مدت، تمدید، تغییر شرح کار؛ مبلغ جاری = مبلغ اولیه + جمع الحاقیه‌ها |
| صورت‌وضعیت | کارکرد **تجمعی**؛ کارکرد دوره = تجمعی − صورت‌وضعیت قبلی (ردشده‌ها حساب نمی‌شوند). کسر حسن انجام کار، بیمه، مالیات علی‌الحساب، استهلاک پیش‌پرداخت (حداکثر تا باقی‌مانده پیش‌پرداخت) و سایر کسورات؛ افزودن ارزش افزوده. همه محاسبات با عدد صحیح ریالی (`bigint`)، گرد کردن نیم به بالا. پیش‌نمایش محاسبه پیش از ذخیره. در هر لحظه فقط یک صورت‌وضعیت باز |
| تأیید صورت‌وضعیت | ارسال به موتور گردش تأیید هسته (کلید `contracts.statement`)؛ ارسال‌کننده نمی‌تواند خودش تأیید کند؛ پس از ارسال قابل تغییر نیست؛ نتیجه با رویداد `core.workflow.completed` روی صورت‌وضعیت اعمال می‌شود |
| تضامین | نوع، شماره، صادرکننده، مبلغ، سررسید، وضعیت (معتبر/آزادشده/ضبط‌شده/منقضی) |
| شرایط پرداخت و تعهدات | مراحل پرداخت با مبلغ یا درصد و سررسید؛ تعهدات ما و طرف قرارداد با مهلت و ثبت انجام |
| هشدار سررسید | کار زمان‌بندی‌شده هر ۶ ساعت: پایان قرارداد و سررسید ضمانت‌نامه در بازه «هشدار سررسید» (پیش‌فرض ۳۰ روز) و موارد گذشته؛ هر هشدار فقط یک بار برای مسئول قرارداد ارسال می‌شود |
| تاریخچه | هر تغییر با جزئیات قبل/بعد در `contracts_history` و Audit Log هسته؛ **هر مشاهده قرارداد در Audit Log ثبت می‌شود** |
| داشبورد | ویجت «قراردادهای جاری» و «سررسیدهای نزدیک» |
| جست‌وجو و KPI | جست‌وجوی سراسری روی شماره/عنوان/طرف قرارداد؛ KPI «ارزش قراردادهای امضاشده» |

## مجوزها

| کلید | محدوده | کاربرد |
|---|---|---|
| `contracts.contract.view` | company / own | مشاهده (own: قراردادهایی که مسئول یا ثبت‌کننده آن هستید) |
| `contracts.contract.create` | company | ثبت قرارداد |
| `contracts.contract.update` | company / own | ویرایش، امضا، پایان/فسخ، الحاقیه، تضامین، شرایط پرداخت و تعهدات |
| `contracts.contract.delete` | company | حذف قرارداد پیش‌نویس |
| `contracts.statement.create` | company / own | ثبت، ویرایش پیش‌نویس و ارسال صورت‌وضعیت |

نقش‌های پیش‌فرض: «مسئول قراردادها» (`contracts_manager`، همه مجوزها) و «مشاهده‌گر قراردادها».

## تنظیمات

`alertDays` (پیش‌فرض ۳۰)، درصدهای پیش‌فرض کسورات: حسن انجام کار ۱۰، بیمه ۵، مالیات ۳، ارزش افزوده ۱۰. درصدهای هر قرارداد هنگام ثبت از تنظیمات پر می‌شوند و بعداً با تغییر تنظیمات عوض نمی‌شوند.

## گردش تأیید پیش‌فرض

هنگام فعال‌سازی برای هر سازمان، اگر گردش `contracts.statement` وجود نداشته باشد، گردش یک‌مرحله‌ای با تأییدکننده «مدیر شرکت» (`company_admin`) ساخته می‌شود. تعریف موجود (ویرایش‌شده توسط سازمان) هرگز بازنویسی نمی‌شود. تغییر آن فعلاً فقط از API `PUT /api/core/workflows/contracts.statement` ممکن است (رابط کاربری تعریف گردش کار هنوز ساخته نشده).

## وابستگی‌ها

- **اجباری:** هیچ.
- **اختیاری:** `projects` (سرویس `projects.projects@^1` برای انتخاب و نمایش پروژه)، `crm` (سرویس `crm.accounts@^1`). در نبود آن‌ها فیلدهای اتصال نمایش داده نمی‌شوند و شناسه‌های ذخیره‌شده حفظ می‌شوند.
- **سرویس عمومی ارائه‌شده:** `contracts.contracts@1.0.0` — `byProject(id)`، `byAccount(id)`، `get(id)` (خلاصه قرارداد با مبلغ جاری و کارکرد تأییدشده).
- **رویدادها:** منتشر می‌کند `contracts.contract.created`، `contracts.contract.activated`، `contracts.statement.approved`؛ مصرف می‌کند `core.workflow.completed`.

## نصب و ارتقا

```bash
pnpm module:pack modules/contracts --out dist/pkgs
pnpm module:sign dist/pkgs/contracts-1.0.0.mypkg --key <private.pem>
```
سپس از کنسول: ماژول‌ها ← نصب ماژول جدید. مهاجرت `0001_contracts.sql` هشت جدول با RLS اجباری می‌سازد. نسخه‌های بعدی باید مهاجرت افزایشی (expand) داشته باشند (راهنمای `modules/hello-module/docs`).

## محدودیت‌های نسخه ۱
- ثبت دریافت/پرداخت واقعی وجه در ماژول مالی (`finance`، فاز ۵) انجام می‌شود؛ این‌جا فقط مبلغ قابل پرداخت صورت‌وضعیت محاسبه و تأیید می‌شود.
- خروجی Excel/PDF و چاپ قرارداد هنوز ساخته نشده‌اند.
- پیوست فایل (اسکن قرارداد) هنوز به رابط کاربری وصل نشده است.
