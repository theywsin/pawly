## ۳. ساخته‌شده‌ها

```
apps/api            NestJS (Fastify) — هسته، کنسول پلتفرم، بارگذار ماژول، entry کلاستر (serve/migrate/create-admin)
apps/web            SPA: ورود/ثبت‌نام، پنل شرکت، کنسول پلتفرم، میزبان ماژول (import map)
packages/module-sdk قرارداد manifest (Zod)، SDK سرور (Ctx، RequirePermission، defineModule)، SDK وب، helperهای RLS
packages/module-package  فرمت بسته، امضای Ed25519، تأیید امن، lint مهاجرت مبتنی بر AST (libpg-query)
packages/ui         کیت UI راست‌چین (Radix + Tailwind)، PageState، ConfirmDialog، Toast، قالب‌بندی شمسی
packages/persian    تاریخ شمسی (Intl)، ارقام، پول، نرمال‌سازی فارسی، کدملی
tools/module-cli    keygen / pack / sign / verify
modules/hello-module  ماژول نمونه کامل + fixtures (ارتقا، مهاجرت خراب، بدون RLS، کد خراب) + راهنمای توسعه
infra               init نقش‌های دیتابیس، Dockerfile، compose مرجع، اسکریپت سرویس‌های محلی
e2e                 Playwright
```

### قابلیت‌های تکمیل‌شده (با تست)
- **احراز هویت:** Argon2id، سیاست رمز، قفل موقت پس از ۵ تلاش، محدودسازی نرخ (Redis)، JWT کوتاه‌عمر + refresh چرخشی در کوکی httpOnly با تشخیص استفاده مجدد و ابطال کل خانواده، خروج از همه دستگاه‌ها، TOTP (بردارهای RFC 6238/4226)؛ ۲FA **اجباری** برای مدیران پلتفرم و کد تازه برای نصب/بازگشت/حذف/کلیدها.
- **چندمستاجری:** RLS اجباری (FORCE) روی همه جداول سازمانی، نقش اپ بدون BYPASSRLS، fail-closed بدون زمینه، محدوده شرکت (`X-Company-Id`) و پایه دسترسی بین‌شرکتی.
- **RBAC:** مجوز با الگو و محدوده (company/unit/project/own)، نقش‌های سیستمی، نقش پیش‌فرض ماژول‌ها، کنترل در سرور برای همه مسیرها (مسیر ماژول بدون مجوز تعریف‌شده = 403).
- **سیستم ماژول:** manifest، بسته امضاشده، تأیید پیش از هر اجرا، بارگذاری آزمایشی در فرایند جدا، مهاجرت‌های تراکنشی با بررسی RLS پس از اجرا، رجیستری، فعال/غیرفعال سراسری و per-tenant (بدون ری‌استارت)، ارتقا (با پشتیبان)، بازگشت نسخه (expand/contract)، حذف نصب با پشتیبان و حفظ داده (یا پاک‌سازی صریح)، تاریخچه عملیات، ری‌استارت چرخشی بدون قطعی، گزارش وضعیت بارگذاری هر نمونه.
- **Entitlement:** پلن/افزونه/مجوز دستی، حالت فقط‌خواندنی پس از انقضا یا تعلیق (بدون حذف داده)، سقف کاربر.
- **زیرساخت‌های هسته:** Event Bus + outbox تراکنشی (at-least-once، idempotent per consumer)، اعلان درون‌برنامه‌ای + SSE، وظایف، موتور گردش تأیید (چندمرحله‌ای با آستانه مبلغ، منع تأیید درخواست خود، یک مرحله برای هر فرد، سقف اختیار نقش)، فایل روی S3 (خصوصی، لینک امضاشده ۵ دقیقه‌ای)، تنظیمات ماژول با فرم خودکار از اسکیما، Widget Registry، جست‌وجوی سراسری مبتنی بر Provider، Audit Log تغییرناپذیر با زنجیره هش و تابع بررسی.
- **SPA:** راست‌چین کامل، حالت تیره، Vazirmatn خودمیزبان، منو/مسیر/ویجت پویا از ماژول‌های فعال، جداسازی خطای ماژول (ErrorBoundary)، همه حالت‌های صفحه، CSP سخت (`script-src 'self'` + hash برای import map).
- **کنسول:** وضعیت سامانه، ماژول‌ها، جادوگر نصب گام‌به‌گام، جزئیات ماژول (فعال‌سازی تکی/گروهی، سراسری، بازگشت، حذف چندمرحله‌ای، تاریخچه)، کلیدهای امضا، مشتریان (مصرف، تعلیق)، رویدادها + بررسی زنجیره.

## ۴. محدودیت‌ها و کارهای باقی‌مانده (صادقانه)

موارد زیر جزو «هسته» در سند ۰۱/بخش ۳.۱ هستند ولی در فاز ۱ ساخته **نشده‌اند** یا ناقص‌اند:

| مورد | وضعیت |
|---|---|

| کانال ایمیل/پیامک اعلان | فقط رابط adapter؛ پیاده‌سازی SMTP نیست |
| صف BullMQ | استفاده نشده؛ outbox با polling و چرخه عمر در فرایند API (A22) |
| ورود داده Excel/CSV، اسکن ویروس، سهمیه فضا، ثبت مشاهده داده حساس | ساخته نشده |
| UI مدیریت نقش‌ها (ساخت نقش سفارشی)، واحد سازمانی، دسترسی بین‌شرکتی، تعریف گردش کار، پلن‌ها | فقط API (یا فقط جدول)؛ رابط کاربری ندارد |
| کنسول: صورتحساب/پرداخت دستی، لیدها، اطلاعیه‌ها، محتوای لندینگ، وضعیت پشتیبان‌گیری | ساخته نشده (بخشی در فاز ۲) |
| پشتیبان‌گیری/بازیابی کل سامانه و آزمون بازیابی خودکار | ساخته نشده (فقط پشتیبان جداول ماژول هنگام ارتقا/حذف) |
| i18n با کلید ترجمه | متن‌ها مستقیم فارسی‌اند (A24) |
| تست دسترس‌پذیری خودکار (axe)، Lighthouse، آزمون بار k6 | اجرا نشده |
| CI (GitHub Actions) | فایل workflow نوشته شده ولی در GitHub اجرا نشده است |
| `docker compose` مرجع | ایمیج ساخته و اجرا شد؛ خود فایل compose (و پروفایل Garage) در این محیط اجرا نشد |

ریسک‌های فنی جدید: (۱) پروژه MinIO دیگر ایمیج Docker عمومی ندارد و Garage در kernel این sandbox کرش کرد — انتخاب S3 مرجع برای استقرار مشتری باید قطعی شود؛ (۲) `exceljs` و `vite-react-ssg` هنوز ارزیابی نشده‌اند (فاز ۲/۳).

## ۵. پیش‌نیاز فاز ۲ و سؤال‌ها

1. **تصمیم شما:** موارد جدول بخش ۴ که جزو هسته‌اند (به‌ویژه زیرساخت گزارش/خروجی، تیکت پشتیبانی و دسترسی موقت، OpenAPI، ایمیل SMTP، پشتیبان‌گیری/بازیابی) را پیش از فاز ۲ تکمیل کنم (فاز «۱٫۵») یا هم‌زمان با فازهایی که به آن‌ها نیاز دارند؟ پیشنهاد من: OpenAPI، SMTP و پشتیبان‌گیری/بازیابی قبل از فاز ۲؛ گزارش/خروجی هم‌زمان با فاز ۳ (اولین ماژول‌هایی که گزارش دارند)؛ تیکت و دسترسی موقت در فاز ۲ همراه کنسول فروش.
2. **S3 مرجع برای استقرار:** Garage، SeaweedFS یا سرویس S3 موجود مشتری؟
3. **مخزن جدا (Q1):** اگر می‌خواهید، اجازه ساخت مخزن جدید یا انتقال به مخزن موجود را بدهید.
4. محتوای لندینگ (فاز ۲): هویت بصری/لوگو و متن‌های تأییدشده.
