# ۰۱ — معرفی محصول و نیازمندی‌ها

> وضعیت: پیش‌نویس فاز ۰ — منتظر تأیید
> نام محصول **مهندیکس** (Mohandix) است (تأیید کارفرما، فاز ۳؛ نام موقت قبلی «مهندس‌یار»). نام و لوگو در وب فقط در `apps/web/src/brand.tsx` و `public/brand/` تعریف شده‌اند. شناسه‌های فنی داخلی (`@mohandesyar/*`، نام دیتابیس، پوشه مخزن) برای جلوگیری از تغییرات پرریسک بدون تغییر ماندند (A32).

## ۱. خلاصه محصول

مهندیکس یک پلتفرم SaaS چندمستاجری و ماژولار برای مدیریت شرکت‌های مهندسی، مشاور، پیمانکار، انبوه‌ساز و هلدینگ‌های عمرانی ایران است. یک هسته واحد، و هر مشتری فقط ماژول‌هایی را فعال می‌کند که خریده است. همه چیز روی سرور خودمیزبان (حتی داخل ایران و بدون اینترنت بین‌الملل) اجرا می‌شود.

## ۲. پرسونا و مشتری هدف

| بخش بازار | اندازه | نیاز اصلی | ماژول‌های محتمل |
|---|---|---|---|
| مهندس مستقل / دفتر کوچک | ۱–۱۰ کاربر | پروژه، قرارداد، اسناد، مشتری | projects, contracts, documents, crm |
| مشاور (معماری/سازه/تأسیسات) | ۱۰–۸۰ | پروژه، جلسات، اسناد فنی، استخدام | + meetings, recruitment, kpi |
| پیمانکار | ۲۰–۳۰۰ | پروژه، تدارکات، مالی/بودجه، QHSE | + procurement, finance, qhse |
| شرکت مدیریت پروژه | ۲۰–۲۰۰ | کنترل پروژه، EAC، گزارش کارفرما | projects, finance, documents, meetings |
| انبوه‌ساز | ۵۰–۵۰۰ | پروژه، تدارکات، فروش، مالی | + crm, procurement, finance |
| هلدینگ | چند شرکت | گزارش تجمیعی و مقایسه‌ای | holding + همه |

نقش‌های کاربری در هر Tenant در سند ۰۶ آمده‌اند.

## ۳. اصول محصول

1. **همه چیز ماژول است**؛ هسته فقط زیرساخت میزبانی ماژول‌هاست (سند ۰۲ و ۰۳).
2. **داده واقعی یا هیچ**: هیچ داده نمایشی/ساختگی. در نبود داده، حالت خالی صادقانه نمایش داده می‌شود.
3. **کنترل سمت سرور**: مجوز، Entitlement و جداسازی Tenant همیشه در سرور (و RLS) اعمال می‌شود.
4. **عدم حذف داده بدون رضایت صریح**: غیرفعال‌سازی ماژول، انقضای اشتراک و تعلیق Tenant هیچ داده‌ای را حذف نمی‌کنند.
5. **بدون هوش مصنوعی** در این نسخه؛ جست‌وجو با PostgreSQL FTS.
6. **خودمیزبان و بدون وابستگی خارجی زمان اجرا** (فونت، CDN، آنالیتیکس، API ابری). سرویس‌های ذاتاً خارجی (پیامک، درگاه پرداخت) فقط از طریق adapter اختیاری و غیرفعال پیش‌فرض.

## ۴. نیازمندی‌های عملکردی (سطح بالا)

شناسه‌ها برای ردیابی در تست‌ها و commitها استفاده می‌شوند.

### هسته (CORE)
| شناسه | نیازمندی |
|---|---|
| CORE-AUTH | ورود با ایمیل/موبایل + رمز (Argon2id)، ۲FA مبتنی بر TOTP، نشست‌ها، خروج از همه دستگاه‌ها، قفل موقت پس از تلاش ناموفق |
| CORE-TENANT | ثبت‌نام Tenant، Company(های) زیرمجموعه، واحد سازمانی درختی |
| CORE-RBAC | نقش، مجوز، محدوده (شرکت/واحد/پروژه/خود)، سقف مالی، سطح محرمانگی |
| CORE-MOD | Module Registry، Loader، چرخه عمر کامل، نصب بسته امضاشده از پنل |
| CORE-ENT | پلن، اشتراک، افزونه، Entitlement سمت سرور، رفتار پس از انقضا |
| CORE-WF | موتور گردش کار و تأیید (ماشین حالت + مراحل تأیید با قواعد تأییدکننده) |
| CORE-NOTIF | اعلان درون‌برنامه‌ای (لحظه‌ای با SSE)، ایمیل (SMTP)، پیامک (adapter) |
| CORE-TASK | وظایف عمومی قابل اتصال به هر موجودیت ماژول |
| CORE-FILE | ذخیره S3-سازگار، لینک امضاشده موقت، اسکن ویروس اختیاری (ClamAV)، سهمیه فضا |
| CORE-AUDIT | Audit Log تغییرناپذیر (append-only + زنجیره هش) |
| CORE-EVENT | Event Bus داخلی + Outbox تراکنشی |
| CORE-REPORT | زیرساخت گزارش: فیلتر، ذخیره فیلتر، Excel/CSV/PDF فارسی، چاپ، زمان‌بندی |
| CORE-DASH | Widget Registry و داشبورد قابل چیدمان |
| CORE-SETTINGS | تنظیمات پلتفرم/Tenant/Company/کاربر و تنظیمات ماژول از روی اسکیمای manifest |
| CORE-SUPPORT | تیکت پشتیبانی، دسترسی پشتیبانی موقت با تأیید مشتری |
| CORE-SEARCH | جست‌وجوی سراسری با Providerهای ماژول‌ها |
| CORE-IMPORT | ورود داده از Excel/CSV با پیش‌نمایش و گزارش خطا (زیرساخت؛ قالب‌ها را ماژول‌ها می‌دهند) |

### پنل ادمین پلتفرم (ADM)، لندینگ (LND)، ماژول‌ها (MOD-*)
به ترتیب در بخش‌های ۴، ۵ و ۸ پرامپت اصلی آمده‌اند و در سند ۰۷ (نقشه صفحات) و ۰۵ (مدل داده) تفصیل شده‌اند. شناسه‌گذاری: `ADM-MODULES`, `ADM-TENANTS`, `ADM-BILLING`, `LND-PRICING`, `MOD-PROJECTS-GANTT`, `MOD-FIN-EAC`، و غیره.

## ۵. نیازمندی‌های غیرعملکردی

| شناسه | موضوع | هدف (قابل تنظیم پس از تأیید) | روش سنجش |

| NFR-REL-1 | RPO | ≤ ۲۴ ساعت (پیشنهاد: WAL archiving برای RPO چنددقیقه‌ای اختیاری) | آزمون بازیابی خودکار |

| NFR-SEC-2 | زنجیره تأمین ماژول | فقط بسته امضاشده با کلید مورد اعتماد اجرا می‌شود | تست رد بسته |
| NFR-OPS-1 | استقلال | استقرار کامل بدون هیچ درخواست خروجی به اینترنت | تست استقرار در شبکه ایزوله (`network: internal`) |

| NFR-MAINT-1 | مرز ماژول | تخطی از مرزها در CI شکست می‌خورد | dependency-cruiser + تست معماری |

## ۶. خارج از دامنه (این نسخه)

- هرگونه قابلیت هوش مصنوعی (و هیچ placeholder برای آن).
- بازارچه عمومی ماژول (ولی فرمت بسته امضاشده آن را ممکن نگه می‌دارد).
- جایگزینی نرم‌افزار حسابداری رسمی یا اتصال به سامانه مودیان.
- اپ موبایل بومی (SPA ریسپانسیو است).
- درگاه پرداخت آنلاین در نسخه اول (adapter تعریف می‌شود؛ پیاده‌سازی: ثبت دستی).
