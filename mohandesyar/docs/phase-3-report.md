> شاخه: `claude/amazing-edison-z40bw3` · وضعیت: **منتظر تأیید برای شروع فاز ۴**

## ۱. خروجی

| ماژول/قابلیت | خلاصه | مستند |
|---|---|---|
| نام و هویت | «مهندیکس» (Mohandix)، لوگو، favicon، تصویر Open Graph، رنگ اصلی از لوگو | `apps/web/src/brand.tsx` |
| زیرساخت مشترک | تبدیل شمسی⇄میلادی (بررسی روزانه ۱۹۸۰–۲۰۶۰ با ICU)، ورودی تاریخ شمسی، ورودی مبلغ ریالی، تب، نوار پیشرفت؛ فهرست اعضا برای ماژول‌ها؛ کار زمان‌بندی‌شده خوشه‌ای؛ `ensureWorkflow`؛ مجوز نقش با محدوده (`key@scope`)؛ تبدیل ساعت تهران⇄UTC | — |
| `contracts` | قرارداد با چرخه امضا، الحاقیه/تمدید، تضامین، شرایط پرداخت، تعهدات، صورت‌وضعیت با کسورات دقیق ریالی و گردش تأیید، هشدار سررسید، تاریخچه و ثبت مشاهده | `modules/contracts/docs` |
| `projects` | تیم با دسترسی در محدوده پروژه، WBS، وابستگی FS/SS/FF/SF، مسیر بحرانی، گانت راست‌به‌چپ، پیشرفت برنامه‌ای/واقعی فیزیکی، زمانی و مالی، منحنی S، موانع، ریسک، گزارش روزانه، درخواست تغییر، تحویل‌ها | `modules/projects/docs` |
| `crm` | مشتری و مخاطب، سابقه ارتباط، سرنخ و تبدیل، قیف قابل تنظیم، فرصت، پیشنهاد نسخه‌دار، یادآوری پیگیری، گزارش فروش | `modules/crm/docs` |
| `meetings` | جلسه، دعوت، دستور جلسه، صورت‌جلسه و حضور، مصوبات با مسئول و مهلت، پیگیری، گزارش معوق و یادآوری | `modules/meetings/docs` |
| داشبورد | فقط از ویجت‌های ماژول‌های فعال (۸ ویجت)، اندازه از manifest؛ «داده کافی وجود ندارد» در نبود داده | — |

اتصال ماژول‌ها فقط از سرویس‌های عمومی: پروژه ← قراردادها (پیشرفت مالی)، قرارداد/پروژه/فرصت ← CRM (کارفرما)، جلسه ← پروژه. با غیرفعال بودن هر ماژول، فیلدهای اتصال پنهان و داده حفظ می‌شود.

## ۲. نتیجه آخرین اجرای تست‌ها

| مجموعه | تعداد | نتیجه |
|---|---|---|
| ESLint + dependency-cruiser | ۲۴۱ ماژول | بدون خطا |
| typecheck (بسته‌ها، اپ‌ها و ۴ ماژول) | — | بدون خطا |
| واحد (persian ۱۱، module-sdk ۷، module-package ۲۹، web ۵، api ۲۱، module-cli ۳، hello ۳، contracts ۱۰، projects ۹، crm ۴، meetings ۳) | ۱۰۵ | همه موفق |
| یکپارچه (PostgreSQL/Redis/S3 واقعی) — ۳۶ تست جدید برای چهار ماژول | ۹۴ | همه موفق |
| سرتاسری Playwright: فاز ۱ (۱۰)، فاز ۲ (۱۰)، فاز ۳ (۷، شامل axe روی ۹ صفحه ماژول‌ها) | ۲۷ | همه موفق |

نکات صادقانه: یک بار اجرای مجموعه یکپارچه با وجود موفقیت هر ۹۴ تست با کد خطا پایان یافت و در اجرای بعد تکرار نشد (علت پیدا نشد). تست‌های E2E و axe اشکال‌های واقعی پیدا کردند که رفع شد: ساختار نادرست `<dl>` در ویجت، کنتراست رنگ «info»، برچسب‌های گانت در SVG راست‌به‌چپ، شروع پیمایش گانت.

## ۳. محدودیت‌ها
| مورد | وضعیت |
|---|---|
| خروجی Excel/PDF و چاپ (قرارداد، صورت‌وضعیت، صورت‌جلسه، گزارش‌ها) | ساخته نشده — زیرساخت گزارش/خروجی هسته هنوز وجود ندارد |
| پیوست فایل (اسکن قرارداد، نقشه و عکس پروژه) | به رابط کاربری وصل نشده؛ مدیریت اسناد در ماژول `documents` (فاز ۵) |
| تقویم کاری در CPM، نسخه پایه برنامه، پیکان وابستگی در گانت | ساخته نشده (A33) |
| UI تعریف گردش تأیید و تغییر تأییدکننده | فقط API (A35) |
| منطقه زمانی | ثابت تهران (A34) |
| کشیدن و رها کردن در قیف فروش | با فهرست انتخاب جایگزین شده |
| مصوبات ↔ وظایف هسته | متصل نیستند |
| Lighthouse برای صفحات پنل | اجرا نشده (فقط صفحات عمومی در فاز ۲)؛ axe روی صفحات ماژول‌ها اجرا شد |
| موارد باقی‌مانده هسته از گزارش‌های قبل (OpenAPI، SMTP، پشتیبان‌گیری کل، CI در GitHub) | بدون تغییر |

## ۴. پیش‌نیاز فاز ۴ و سؤال‌ها
1. فاز ۴ طبق پرامپت: `recruitment` ← `hr` ← `kpi`. پیشنهاد: پیش از آن **زیرساخت گزارش/خروجی Excel و PDF فارسی** ساخته شود، چون همه ماژول‌های فعلی و بعدی به آن نیاز دارند.
2. آیا تقویم کاری (تعطیلات رسمی) برای زمان‌بندی پروژه لازم است؟
3. سؤال‌های باز قبلی (SMTP، S3 مرجع، مخزن جدا) هنوز باز هستند.
